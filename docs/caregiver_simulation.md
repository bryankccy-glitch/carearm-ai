# 照護者確認後執行：實驗擴充

本功能是探索性研究工具。正式實驗前須先由研究者在 `RESEARCH.md` 預先登記；本次未修改該檔，也未執行正式大實驗。

## 使用方式

在本 worktree 執行（不要切回主工作目錄）：

```bash
export PYTHONPATH="$HOME/Desktop/ml"
export MPLCONFIGDIR=/tmp/carearm-confirm-mpl
"$HOME/Desktop/ml/carearm-ai/.venv/bin/mjpython" -m carearm.experiments.runner \
  --run-id caregiver_smoke --n 60 --seed 20261124 \
  --caregiver-error 0.05 --caregiver-seed 20261124 --smoke
"$HOME/Desktop/ml/carearm-ai/.venv/bin/mjpython" -m pytest -q tests
```

`--caregiver-error 0` 啟用理想照護者；`0.05` 表示每個送審情境有 5% 機率翻轉批准／拒絕決定。省略此參數即停用，保留原本輸出欄位與統計。機率接受有限的 0 至 1 數值；它是設定值，不保證有限樣本中的實際錯誤比例恰好等於該值。

照護者不參與 train／calibration，也不調整任何模型、門檻或情境。啟用時訓練演算法相同，但模型產物寫入本次 run 目錄，避免覆寫既有 `models/`。新功能與舊功能使用不同 run-id；不要讓不同設定共用同一個輸出目錄。續跑時必須維持相同情境數、種子、profile 與 alpha（現有快取不驗證這些設定）。

## 決定與執行語意

- 僅處理 `REQUEST_CONFIRMATION`；自動執行與 `STOP` 保留原行為。
- 依 `should_execute` 真值批准或拒絕，再依錯誤率翻轉。SHA-256 的 `seed:scenario_id` 前 64 位元映射到 [0, 1)，不消耗情境／模型的亂數；同情境跨策略共用抽樣，與遍歷順序無關。
- 批准沿用原決策時段與座標，不修正錯盒，不使用真值位置。呼叫原 `ExperimentRunner.execute`，因此共用 `(scenario, period, x, y)` 物理快取；缺快取就真的執行 MuJoCo。
- 有失敗的硬性 `STOP` 規則時不執行。缺目標（例如未知意圖、時段不明或 Layer 1 未產生座標）也不猜測；以「批准未執行」獨立列出。這類情境要讓真人澄清／重選目標，需另一個預先定義的實驗介入，本次未加入。
- 照護者錯誤是批准／拒絕決定錯誤，與後續物理失敗分開。理想照護者批准也可能夾取失敗或送錯盒。

## 輸出與分母

`test_decisions.csv` 啟用時新增 `caregiver_*` 欄位，包括是否送審、是否批准、決定是否錯誤、是否執行、物理成功、送達盒、失敗階段、模擬時間與是否正確。原 `executed`／`correct` 仍只表示自動執行。

新增 `caregiver_metrics.csv`、`caregiver_report.md`，並在 `summary.json` 加入照護者指標與設定；`run_meta.json` 記錄錯誤率、種子、抽樣方法及試跑標籤。

| 指標 | 定義 |
|---|---|
| 確認後正確完成率 | 確認後正確送達數 ÷ 確認後實際執行數 |
| 確認後執行錯誤 | 列出錯誤件數，錯誤率 = 不正確執行數 ÷ 確認後實際執行數；包含不該取卻取、錯盒與物理失敗 |
| 照護者負擔 | 100 × 送審次數 ÷ 全部測試情境；批准、拒絕都算一次審查，不是只算批准 |
| 端到端正確取藥率 | 自動正確完成數與確認後正確完成數的聯集 ÷ 全部測試情境 |

無確認後執行時兩個條件率未定義（CSV 空白、JSON null）。拒絕及批准未執行不算執行錯誤，也不算正確取藥；另列數量避免隱藏未完成。端到端分母沿用既有正確取藥率，包含不應取藥情境，正確拒絕不算取藥成功。新指標僅描述，不新增假設檢定或風險保證。

## 回歸證據與限制

`tests/fixtures/caregiver_legacy_*` 是從修改前提交 `a1296d57a810cabed819242c27810c5236813016` 的 runner／report 對固定合成輸入產生。不是物理實驗成績。測試比對停用功能時完整決策列、summary 及 metrics／stats／pairwise CSV 位元組；bootstrap 固定 30 次以縮短測試。另驗證新增欄位不改自動結果、CSV 讀回報告、無執行分母、錯誤率邊界、種子重現性、原提案路由及快取只呼叫一次執行器。

圖檔不做跨平台位元組比較；真實 MuJoCo 的新增端到端路徑仍須以成功的小型試跑驗收。合成測試中的執行器替身不代表物理成功。

## 正式實驗應先預先登記的建議

請研究者在 `RESEARCH.md` 先定案以下內容，再執行，不能由本次試跑倒推成立條件：

1. 程式提交、固定的情境分佈／樣本數／train-calibration-test 比例／alpha；情境 seed、照護者 seed 清單；停止、失敗重跑與中斷保存規則。
2. 明確定義照護者只批准原提案的能力假設；對缺目標、硬性停止、批准未執行的處理；真值只供照護者決定與評估，不修正機器感知。
3. 錯誤率 0 與 0.05 各自獨立報告，並預先指定跨策略／錯誤率的配對抽樣設計；不要事後換 seed 挑結果。
4. 四個指標的分母、原始件數、拒絕及未執行數；指定主要策略比較、假設方向、成立標準與多重比較校正。
5. 情境層級配對分析及預先選定的區間估計；對稀少／零錯誤預先採合適的二項區間（例如 Clopper–Pearson），不要把零錯誤 bootstrap 上界當作安全保證。
6. 與既有正式結果分開，不合併選擇性分析；說明真值照護者是假設模型，錯誤率未經真人實測，結果限於 MuJoCo 與文字 ASR 模擬。
